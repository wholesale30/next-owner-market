# Rules Harvest: pull every lesson from every project into the master files

*Made October 23, 2026. Use this to collect everything each project and chat has learned (rules, mistakes, fixes, workarounds) so it can all be merged into the master files: the shayne-operating-rules skill, the App Builder's Playbook and the Operating Rules.*

## How to use it (3 steps per project)

1. Open the project and start a **new chat** inside it. (Chats outside any project: start one plain new chat for those.)
2. Paste the **whole prompt below** and send it. Claude makes a Word file and gives it to you.
3. Bring that Word file back to the Next Owner Market chat and upload it. Claude merges it into the master files and sends you the updated zip.

Do one project at a time. Each Word file is named for its project, so they never get mixed up.

## The prompt to paste

> **RULES HARVEST. Do this completely before anything else.**
>
> I'm collecting everything this project has learned so it can go into my master rules for my whole Claude account. Make me ONE Word file (.docx) named `Lessons_Export_<this project's name>_<today's date>.docx` and give it to me as a download.
>
> **Where to look, in this order:** this project's instructions and every file in its knowledge; every past chat in this project you can reach (use chat search if you have it); any rules, CLAUDE.md, Operating Rules, Lessons or Playbook files in this project's code or documents; your memory of me. At the top of the file, list exactly what you could and could NOT reach, so I know what's missing.
>
> **Rules for writing it:**
> - Use only what is actually in this project or its chats. Never invent, guess, or fill gaps from memory. If you're unsure, write "unsure" and say why.
> - Quote my exact words wherever I stated a rule, got angry about something, or praised something, with the date.
> - Plain English. Every item gets a date.
>
> **The file must have these sections, in this order:**
> 1. **What this project is**: name, what it's for, its website, repo and database names if any, and key people.
> 2. **My rules**: every rule or preference I've stated (how to talk to me, formats, files, costs, phone use, design, anything). My exact words plus one line on what it means in practice.
> 3. **Mistakes and fixes**: every time Claude got something wrong. For each: what happened, my reaction (quoted), why it happened, the fix, and the rule that stops it happening again. Number them P-1, P-2, P-3…
> 4. **Workarounds and back doors**: every trick that made something work (tool quirks, settings, outside services, things that get blocked or cancelled and what worked instead). Exact values and steps.
> 5. **Outside services used**: what each one does, how it's connected, its cost and free limits, and gotchas.
> 6. **Facts to never get wrong**: about me, my business, my accounts, numbers, names.
> 7. **What worked and should be repeated**: methods, formats, prompts, designs I liked.
> 8. **Open items**: anything unfinished, waiting on me, or promised but not done.
> 9. **Conflicts**: anything here that disagrees with another rule (say both sides, and which one I said last).
> 10. **Suggested master rules**: the 5 to 15 most important lessons from this project, written as short rules ready to paste into my master skill.
>
> When the file is done, tell me in two lines how many rules, mistakes and workarounds it found, and give me the download. Don't change anything else in this project.

## What happens when you bring the files back

Claude (in the Next Owner Market chat):
1. Reads every export.
2. Merges new rules into the shayne-operating-rules skill (you'll get a card to tap Save), the App Builder's Playbook (new T- numbers in Part 2 section 11, new services in 4B), and the Operating Rules.
3. Updates the "Warehouse items" project copies.
4. Sends you the one dated zip with everything.
5. Lists any conflicts between projects so you can pick which rule wins.
